把 QQ 接到这台 Linux 服务器

服务器上同时运行 Hub 与 NapCat，你在手机上的 QQ 给机器人账号发私聊。知微使用 config/zhiwei-profile.md 里的人格，Codex CLI 负责生成回复或执行任务。

1. 登录机器人 QQ

准备一个独立的 QQ 账号作为机器人，与你的管理员账号互加好友。按 NapCat 官方文档在这台机器上安装 NapCat（Linux 无桌面环境时需要 xvfb-run）。

管理员账号与机器人账号必须不同；管理员继续在手机上正常使用。

2. 写入两个 HTTP 连接

初始化时如果给了 --napcat-dir，项目已经生成 onebot11_<机器人QQ>.json，直接放进 NapCat 的配置目录即可。也可以在 NapCat「网络配置」里手工填写：

  • HTTP 服务端：启用，Host 127.0.0.1，端口 3000，Token = data/local.json 里的 oneBotAccessToken。
  • HTTP 客户端：启用，URL http://127.0.0.1:3789/api/onebot/event，Token = data/local.json 里的 oneBotSecret。
  • 消息格式选 array，关闭「上报自身消息」。保存后让连接生效。

两个 Token 用途不同，分别复制。不要把它们发到任何群或仓库。

回到首页刷新，或在项目目录运行 npm run doctor，应看到 QQ 桥接器在线。

3. 在手机上试用

/帮助
/状态
用生活中的例子解释惯性

/执行 在工作目录创建一个 hello.txt，内容为你好
/确认

普通聊天不会进入写文件模式。每个 /执行 任务需要在 3 分钟内确认；/取消 只取消待确认任务。执行结果回到管理员私聊。

4. 自定义 Skill 与任务

普通聊天默认使用知微人格。需要自定义 Skill 时，在 data/local.json 的 skills 里添加路径，重启后用 /技能 查看并选择；/技能 none 恢复默认。

继续任务时，发送 /执行 你的补充或下一步 并确认。较长任务请拆成多次；单次超时为 10 分钟。

任务默认只能写入 workspace 指定的目录。/执行完全访问 需要显式打开 allowFullAccessTasks，请先阅读 docs/security.md。
