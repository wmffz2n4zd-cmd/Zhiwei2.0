# 安全与隐私边界

> English: [docs/en/security.md](en/security.md)

这套系统的定位是**单人、单机、私有**。下面写清楚哪些是设计保证，哪些只是“尽力而为”，以及你可能踩到的地方。

## 1. 信任边界

- Hub 只监听 `127.0.0.1`，不对外提供端口。
- 只响应 `ownerUserIds` 里的私人 QQ；群消息在进入模型之前就被丢弃，发送端另外拦截所有群 API。
- 出站包括给 NapCat 的消息请求、Codex CLI 发起的模型请求，以及手动或生活活动触发的网页读取。模型输入可包含当前消息、召回的私聊历史、画像及图片；本地持久保存不等于内容不出站。本项目没有额外遥测通道。

**所以：不要把这台机器共享给不信任的人，也不要用反向代理把 3789 暴露到公网。**

## 2. 本机 HTTP 没有认证

这是最需要你知道的一条。`/api/state`、`/api/maintenance`、`/api/memory` 等接口**没有登录凭证**，只靠两个检查：

1. `Host` 必须是 `localhost` / `127.0.0.1`（挡 DNS 重绑定）；
2. 写操作要求同源 `Origin`。

后果：**这台机器上任何能发 HTTP 请求的进程，都能读到记忆摘要、改通道开关**。单用户服务器可以接受；多人共用的机器不行。

另外 `/api/qq/event` 名义上是“预览回复、不发送”，但它会执行指令的副作用（例如 `/ban` 会落盘）。不要把它当成纯只读接口。

## 3. 密钥

| 位置 | 内容 | 处理 |
| --- | --- | --- |
| `data/local.json` | QQ 号、OneBot 两个密钥 | 权限 600，`.gitignore` 忽略 |
| `data/world/browser-profile/` | 网站登录 Cookie | 敏感，等同密码 |
| 实际 `CODEX_HOME`（默认 `~/.codex/`） | 模型登录及CLI会话资料 | 认证由CLI管理，不随仓库或公开备份分发 |
| `napcat-data/` | QQ 登录态 | 敏感 |

`napcat-data/` 只是示例位置；实际配置、缓存与登录态目录由你的 NapCat 安装决定。`tmp/qq-images/` 的私聊图片和 `runtime/` 的输出/诊断也属于敏感运行数据，应与 `data/` 一起排除出 Git 提交。

`npm run setup` 为每个实例生成独立密钥，不存在“默认密钥”。如果 `data/local.json` 泄露，改掉两个 Token 并同步改 NapCat 配置即可，不需要重装。

## 4. `/执行` 与完全访问

- 普通 `/执行`：Codex 在 `workspace` 目录内以 `workspace-write` 运行，每个任务要 `/确认`，3 分钟内有效。
- `/执行完全访问`：`danger-full-access`，能读写工作区外文件、访问网络。**默认关闭**（`allowFullAccessTasks: false`）。启用后模型可在实际服务用户的系统权限内执行命令，请只在你能接受后果时启用。

这两种任务的输入都来自你自己的 QQ 私聊。**如果你在别处泄露了管理员 QQ 的登录，攻击者就能通过它在你机器上执行命令。** 这是整条链路里权限最高的一环。

## 5. 网页阅读不是沙箱

`docs/architecture.md` 里描述的白名单、禁下载、禁 WebSocket、只读 POST，全部是**应用层策略**，不是操作系统隔离。仍然存在：

- 恶意页面通过文字内容做提示注入（模型能看到页面文字，虽然该路径关闭了工具调用）；
- 浏览器自身漏洞；
- DNS 重绑定（代码里有私网/保留地址拒绝，但不能替代网络层隔离）；
- 站点改版导致“以为读到了、其实读到的是导航页”（代码会识别登录页并清空正文，但不能覆盖所有版式）。

想让浏览更安全，就在容器或独立网络命名空间里跑，而不是指望应用层白名单。

## 6. NapCat 与 QQ 账号

NapCat 是第三方、非官方的 QQ 协议端，通过注入 QQ NT 客户端工作。它不在本仓库内，也不受本项目控制。使用它有**账号被风控或封禁**的现实风险；本项目不做任何规避，也不保证稳定。请用一个小号做机器人，不要用你的主号。

## 7. 日志会含内容

- `runtime/replies/*.txt`：模型的原始输出（含对话内容）。
- `runtime/logs/cli-error-*.json`：CLI 失败快照（可能含提示词片段）。
- `data/unified-memory.json`、`data/life/journal.jsonl`：完整的个人历史。
- `tmp/qq-images/`：接收图片的本地副本；不是匿名素材。

这些是隐私数据，和密码同级对待。报 issue 时不要贴原文。

## 8. 供应链

运行期依赖只有 `playwright-core`（Apache-2.0），版本由 `package-lock.json` 锁定，`npm ci` 安装。Codex CLI、Node.js、NapCat、Chromium 都由你自己安装，本仓库不打包它们。

## 9. 已知的、没有修的问题

坦白列出，避免你有错误预期：

1. 本机 HTTP 无认证（见第 2 节）。
2. `/api/qq/event` 名义预览、实际会执行指令副作用。
3. `GET /api/platform` 会返回管理员 QQ 号。
4. `settings.json` 非原子写；解析失败会静默回落到默认值，下一次保存可能把你的自定义项覆盖掉。
5. 进程崩溃时，已经 ACK 但还没入库的消息会丢（没有入站重放队列）。
6. 没有单实例锁：换端口起第二个进程会并发写同一份 `data/`，务必只跑一个。
