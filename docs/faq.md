# 常见问题

> English: [docs/en/faq.md](en/faq.md)

**她会主动找我吗？多久一次？**
会，但不是定时问候。主动联系需要时间线里恰好有一个“想找人说话”的念头变成活动，并且满足：距上次来信至少 10 分钟、对方最近 30 天内来过、同一对象 6 小时内没被考虑过。任何一条不满足就不发。没有配额，也没有“每天必须联系一次”的逻辑；几天不主动是正常结果。

**为什么装好之后她一直很安静？**
三种可能，按顺序排查：① 生活时间线没开（`life.enabled`）；② 最近一次规划只排了模拟活动，没有联系念头，下一次规划在 4–24 小时后；③ 唯一联系人被标记过“暂停联系”（发过明确的“别找我了”）。观察台能看到念头与活动记录，没有记录就是真的没有。

**为什么回复有时很慢？**
生成是一次 Codex 子进程调用，默认超时 300 秒；慢在模型侧，不在本项目。同一个人连续发消息会排队，不会并发生成。

**为什么她一次发好几条消息？**
普通回复允许用空行分成最多 3 段，逐段按序发送，模拟真人连发。短回答、指令回复、结构化内容不会被拆。

**她会编造“我今天读了某本书”吗？**
设计上不允许。计划、进行中、完成、失败是不同状态；只有真实完成的阅读才会成为外部经历，网页读取还会带来源。没有记录时她只能说想做什么，不能说已经做过。

**能拉她进群吗？**
不能。这个版本只支持私聊：群消息在进入模型前被丢弃，发送端也拦截群 API。`qqPrivateOnly` 不接受配置关闭。

**能换成我自己的角色吗？**
能。改 `config/zhiwei-profile.md`，或用 `assistantProfile` 指向你自己的文件，再或者设环境变量 `CODEX_REMOTE_CONTACT_ASSISTANT_PROFILE_PATH`。人格文件每次都重读，改完不用重启。

**能换模型吗？**
能。`data/local.json` 的 `chatModel` / `chatReasoningEffort`，或私聊里发 `/私聊模型 名称`、`/私聊智能等级 low|medium|high|xhigh`。模型必须是 `codex login` 的账号可用的名字。

**她记得我说过的话吗？**
记。按 QQ 号隔离存在 `data/unified-memory.json`，画像只保存明确自述的称呼与喜好，支持更正、撤回和容量裁剪，不自动归纳交流习惯或按时间淡化。最近 2 小时的对话可作为有界近期上下文带上，更早的依据关键词等条件检索；必要内容会随当前消息交给模型服务。

**“额度受限”是什么意思？**
说明 `runtimeBudget.mode` 是 `strict` 且没有校准记录。默认是 `observe`：只记账不拦截。但 observe 不等于免费——额度仍然花在你自己的账号上。

**支持 Windows / macOS / ARM 吗？**
这个发行版只针对 Ubuntu 24.04 x86_64。上游的 macOS 原生通道（iMessage、Shadowrocket、背光控制）代码还在，但在 Linux 上不会激活，也不在支持范围内。ARM 未验证。

**能不能不接 QQ？**
不能。这个发行版唯一的通道就是 QQ 私聊（经 NapCat 转 OneBot）。

**数据怎么搬走 / 怎么彻底删掉？**
主要持久状态在 `data/`，私聊图片在 `tmp/qq-images/`，输出与诊断在 `runtime/`；NapCat、Codex认证及自定义工作区可能在仓库外。按[备份范围](operate.md)分别保全这些位置。仅移除 `data/` 既不是完整迁移，也不会清除其他位置的敏感内容；且会同时失去本项目配置，重新初始化前不能正常接收私聊。清理或恢复前先停止服务并确认要保留的范围。

**观察台打不开？**
它只允许本机回环访问，并且拒绝带 `X-Forwarded-*` 的请求。服务器上请用 SSH 端口转发：`ssh -L 13789:127.0.0.1:3789 用户@服务器`，然后访问 `http://127.0.0.1:13789/life-observer.html`。

**多个 QQ 号都能聊吗？**
默认只有 `ownerUserIds` 里的号。打开 `allowOtherPrivateChats` 会让任意陌生人也能聊，并各自留下记忆和画像——不建议。

**重启会不会丢东西？**
正常停止不会：服务会等已接收的消息与写入完成（最长 600 秒）。强制 `kill -9` 或断电可能丢掉已 ACK 但未入库的最后几条。生活时间线有哈希链和半行修复，重启后不会重复执行旧活动。

**把备份或旧版本的 `data/` 拷回去之后，服务启动失败，日志说 life journal 无效？**
生活时间线是带哈希链和序号的追加日志（`data/life/journal.jsonl`）。手工编辑、只覆盖其中一部分文件、或把不同版本的 `data/` 混在一起，都会让校验失败。程序的处理是**拒绝启动并保留原文件**，而不是悄悄丢弃或重写你的历史。正确做法：停服务，整体替换整个 `data/`（不要只挑几个文件），再启动；实在无法恢复时，把 `data/life/` 移走让它重建（会丢失生活历史，聊天记忆不受影响）。

**她会不会一直发“我在”？**
早期版本在纯图片消息上确实有这个问题，已经修正为按“正文 / 图片 / 引用 / @”分别描述。如果还遇到，请连同当时的消息形态一起反馈。
